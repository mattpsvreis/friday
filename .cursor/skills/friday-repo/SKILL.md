# Friday repository

Friday (`package.json` name `Friday`) is a single-package Next.js app. `pnpm-workspace.yaml` holds pnpm settings only. It is not a multi-package workspace.

## Toolchain

- Package manager is **pnpm**. The lockfile is `pnpm-lock.yaml`. Use pnpm for install, add, remove, and scripts. Never use npm, yarn, or bun, including the alternatives listed in `README.md`.
- Node.js is **24**, pinned in `.nvmrc`. Match that version before installing or running. `@types/node` is still the `^20` range; that package is types only. Do not downgrade Node to match it. If the types get in the way, bump them with `pnpm add -D @types/node`.
- App framework is `next@16.4.0` and React 19. Routes live in the App Router (`app/`). There is no `pages/` router and no `src/` directory.
- Language is TypeScript with `strict: true`. The `@/*` path alias maps to the repo root.
- Styles are Tailwind CSS 4, configured in CSS. There is no `tailwind.config.js`.

## Commands

Run these from the repo root:

| Task | Command |
| --- | --- |
| Install | `pnpm install` |
| Dev server | `pnpm dev` (http://localhost:3000) |
| Production build | `pnpm build` |
| Production server | `pnpm start` |
| Lint | `pnpm lint` |
| Add a runtime dependency | `pnpm add <name>` |
| Add a dev dependency | `pnpm add -D <name>` |
| Remove a dependency | `pnpm remove <name>` |

After dependency changes, keep `pnpm-lock.yaml` in the commit. Do not commit `node_modules`, `.next`, or env files.

## Before editing Next.js code

This Next.js version differs from older releases. `AGENTS.md` is regenerated by `next dev`. Leave the `nextjs-agent-rules` block intact, including when it reappears as an uncommitted change.

1. If `node_modules/next` is missing, run `pnpm install`.
2. Read the relevant guide in `node_modules/next/dist/docs/` before changing routes, layouts, data fetching, caching, config, or fonts.
3. Follow deprecation notices in those guides.

Do not replace App Router files with a `pages/` router. Leave these `next.config.ts` settings in place unless the user asks to change them:

- `cacheComponents: true`
- `partialPrefetching: true`
- Turbopack rule for `*.css` using the `@tailwindcss/turbopack` loader

Treat `cacheComponents` and `partialPrefetching` as defined by the installed docs. Do not substitute older Partial Prerendering patterns from memory.

## Where code goes

- `app/layout.tsx` — root layout. Props type is `LayoutProps<"/">`. Fonts are Comfortaa + Source Serif 4 via `next/font/google`.
- `app/(app)/page.tsx` — dashboard (auth-gated shell).
- `app/globals.css` — Tailwind entry and neon dark theme tokens.
- `next.config.ts` — the only Next config.
- `tsconfig.json` — compiler options and `@/*`.
- `eslint.config.mjs` — flat config from `eslint-config-next` (core web vitals and TypeScript).
- `public/` — static files served from `/`.

New UI routes go under `app/`. Import with `@/` when a relative path would climb out of the current folder. `LayoutProps` and other generated Next types come from the installed package; do not redeclare them.

## Tailwind

Put utilities on `className`. Change shared colors and font tokens in `app/globals.css` (`:root`, the dark `prefers-color-scheme` block, and `@theme inline`). Do not add `tailwind.config.js` or a second PostCSS Tailwind pipeline. CSS is compiled by the Turbopack loader declared in `next.config.ts`.

## pnpm settings file

`pnpm-workspace.yaml` currently contains only:

```yaml
allowBuilds:
  unrs-resolver: true
```

That allows the `unrs-resolver` dependency to run its build script. Leave the entry when adding packages. Do not add a `packages:` list unless the user asks for a workspace. If pnpm blocks a new dependency's build script, ask before widening `allowBuilds`.
